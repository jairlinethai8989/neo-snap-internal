# Neo Snap for Windows

Internal Windows screen capture and image annotation app for company use. Standalone Windows capture app; the Chrome extension is not required. This build targets Windows 10 (2004+) and Windows 11, x64.

## Install

Run `dist/Neo-Snap-Windows-Setup-0.1.18.exe`. Exit the running app from its tray menu before updating. The unsigned installer may show a Windows SmartScreen warning. Setup offers checked-by-default shortcut and launch options. Launch waits until the completion notice is dismissed and setup exits. Missing prerequisites suppress automatic launch. Existing SnapCraft data and installation paths are preserved for upgrades.

The current installer requires [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0), [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/), and the [Visual C++ x64 Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe). It checks these after installation and shows download links if any are missing. No administrator permission is required for SnapCraft itself.

## Use

- **Combine images:** the Layers button selects images from open editor tabs/windows and creates a new editable workspace. Choose vertical, horizontal, or free arrangement and spacing. Source tabs remain unchanged. Add Image accepts files, clipboard images (including Ctrl+V), or other capture tabs. Use Workspace Size to make room for manual arrangement.
- **Image layers:** select and drag an image, resize its bottom-right handle with its aspect ratio retained, or enter a width/height in the image toolbar. Image movement/resizing carries its imported editable annotations. Their rendering is clipped to that image. Crop with an image selected crops only that image; deselect it to crop the whole workspace. Image front/back ordering moves its attached annotations together. Delete removes the image and its owned annotations; Clear removes annotations but preserves image layers. Undo/redo covers these operations.
- **Editable projects:** Save Work writes a self-contained `.neosnap` document; Open Work is available in the launcher and editor. PNG export remains separate. Project files retain original, unredacted images even after crop/blur/opaque masking; share exported PNGs with recipients who must not see originals. Closing a changed project offers project save by default, with PNG as an alternative. Versioned validation rejects external image references, invalid coordinates and oversized work before replacing current state. Limits: 100 image assets, 5,000 objects, 80 million retained source/workspace pixels, 32,767 pixels per workspace side, and 180 MB project files. Very large jobs should be split. Automatic crash recovery is not included.

- **Area:** drag a rectangle on the screen.
- **Window:** click a window.
- **Scroll:** point at a window and click the red frame. For canvas sheets with persistent column borders and a broad colored header, the frame excludes application toolbars while retaining the sheet's column labels and frozen headers. UI Automation containers are used when available; otherwise the window's client area is retained. Hold Ctrl and drag for an exact custom region. Stationary headers appear once at the top and detected stationary footers once at the bottom. `Esc` or **Finish** keeps the partial image; **Cancel** discards it. Use **Manual** when automatic scrolling cannot move the target.
- **Video:** choose screen or window and audio options. A 3-2-1 countdown precedes recording. A topmost REC controller displays elapsed time, Stop, and Cancel. **Stop** finalizes the MP4 and opens a playable local preview, without an immediate Save dialog. Choose **Copy Clip**, **Save MP4**, or drag the grip icon into another app. **Cancel** during recording discards it. There is no 30-second limit. The controller is excluded from capture when Windows supports display affinity.
- Captured images open in the editor for crop, drawing, text, blur, and PNG export. Choose whether new captures open as tabs or windows in the toolbar settings.
- Screenshots keep native source pixels and lossless PNG by default; there is no separate quality preference. Fit / 100% controls change the editor view only, not the image dimensions or saved pixels. At 100%, one image pixel occupies one CSS pixel; Windows/WebView display scaling still applies. Scroll both axes to inspect large images.
- Outline and filled shape groups offer rectangles and circles. Blur uses a crisp droplet icon with the tooltip "เบลอเฉพาะพื้นที่". Drawing tools remain active until another tool is selected.
- The launcher image button browses PNG, JPEG, BMP, GIF and TIFF into independent editor copies without modifying originals. Project files still open from the editor.
- Drawing and text start red; the highlighter remains translucent yellow. Explicit color choices are retained.
- Selected lines and arrows have a midpoint handle for bending. Curves retain patterns, shadows and editable geometry through undo, moving, resizing, combining and project saves.
- The opacity slider edits the selected object's transparency in real time. The highlighter defaults to translucent yellow and uses multiply blending to preserve dark text. A 66-color palette includes recent and custom colors. Copy shows a busy state and a temporary success checkmark. Each native editor tab has its own themed close icon.
- Pen, straight line, arrow shaft, rectangular outline, and elliptical outline offer solid/dashed/dotted strokes, defaulting to 5 image pixels. Change a selected object's pattern, width, or opacity immediately; changes are undoable. Arrow heads remain solid. Highlight, text, and numbered-marker defaults remain suitable for their tools.
- Every annotation has an optional shadow with its own palette color, blur and signed horizontal/vertical offsets. Select an item to edit it immediately, or configure a shared preset before drawing. Shadows do not affect the background or weaken protected blur regions. Text has an independent optional outline with its own color and thickness. Shadow and outline may be combined.
- The speech-bubble tool creates editable text inside a rounded box and attached tail. Move it as one object, resize its box without stretching the font, and double-click to edit. Text wraps at word boundaries with long-word fallback; the box grows to keep lines visible. Fill, border and text colors are independent. Effects and bubbles survive undo/redo and appear in copied/saved PNGs.
- Select a speech bubble and drag its circular blue tip handle to point in any direction; the square handle resizes only the body. The tail moves with the bubble and survives text edits, resize, crop and undo/redo. Arrow keys move a focused tip handle by one image pixel, or ten with Shift. Handles never appear in PNG exports.
- The numbered-circle tool places labels per captured image. The next number is one greater than the highest number still present. Deleting the latest marker reuses it; deleting a middle marker does not renumber the others. Undo/redo/clear affect the next number; a new capture starts at 1.
- Video previews protect unkept clips with Save / Discard / Cancel. Copy uses the Windows file-drop clipboard, not a text path or thumbnail, and the source remains available after closing. Clip paste support depends on the destination client; LINE PC supports dragging video files, but clipboard paste still needs real-client verification. The app never sends chat messages automatically.
- Retained clips stay under `%LOCALAPPDATA%\SnapCraft\Recordings\Clips`. On startup, clips older than seven days are cleaned up unless open or referenced by the current file-drop clipboard. User-saved destinations are never cleaned up. MP4 save uses a temporary sibling then atomic replacement, preserving the original clip and any previous destination on failure. Canceling Save As leaves the preview open.
- Capture buttons distinguish selected mode from actual running capture. The compact launcher clears old capture status when reopened and is not permanently topmost. Settings/audio dialogs temporarily enlarge it. Version and About identify the developer as jairlinethai.
- New images and edits are protected by Save / Discard / Cancel when closing a tab, the editor window, or exiting the app. A successful PNG save or clipboard copy keeps that exact image state; newer edits warn again. Canceling a save or a failed write keeps the image open. Clipboard copy is not a persistent backup; crash recovery remains planned.
- PNG save writes a temporary sibling before replacing the chosen output. A failed replacement preserves the previous file. Closing waits for pending saves and WebView initialization, and checks captures arriving during a window-close operation too.
- Every video start asks for system audio and/or microphone, with a separate silent-recording option.
- If both GPU recording backends fail, recording falls back to CPU/GDI using an installed FFmpeg executable. This PC already has FFmpeg; on another PC, About shows an optional WinGet installation button if it is missing. SnapCraft does not bundle or redistribute FFmpeg.
- CPU window capture records the visible screen rectangle. Keep the target visible, unminimized, stationary, and unobstructed. CPU capture uses 20 fps and may use more CPU than the native methods.
- CPU audio is recorded with NAudio WASAPI, including silent gaps, and muxed as AAC when stopped. Requested sound is never silently disabled. Failed finalization retains intermediate files and reports their location.
- Native attempts, raw CPU recordings, and finalized MP4s use distinct paths. A failed native encoder's locked output cannot block CPU audio muxing. Native recorder resources are released before the saved file is copied.
- Recording diagnostics are saved under `%LOCALAPPDATA%\SnapCraft\Logs`; no logs or recordings are uploaded.
- Window, area, and scroll screenshots first copy visible screen pixels directly, without scaling or starting a GPU recorder for every frame. Windows Graphics Capture/Desktop Duplication remain fallbacks for unsupported screen-copy paths. GPU screenshot attempts now time out after 3 seconds, not 15.
- The selection overlay is modeless and nonactivating. It preserves the existing foreground window and uses a global Esc hook to cancel selection. Repeated scroll input no longer calls SetForegroundWindow when the target is already foreground. Stitching and PNG output run off the UI thread.
- Sheet framing uses conservative image evidence, not a fixed toolbar height. Original width, horizontal scroll position, and pixel scale are retained. Detection is not a guarantee for every app; Ctrl-drag remains available for unusual layouts. The capture starts from the current viewport; it does not deliberately jump to a selected cell or the top of the document.

UI Automation probes run off the UI thread, following [Microsoft's threading guidance](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-threading-issues). Audio uses the bundled ScreenRecorderLib 7 audio-source API, described in the [project's options](https://github.com/sskodje/ScreenRecorderLib/blob/master/ScreenRecorderLib/Options.h).

## Verify on a real desktop

This build passed synthetic stitching, real captured-frame regression, and asset checks. Local desktop smoke tests captured a nonblank display and window, encoded H.264 MP4 from both, and scrolled a test window to its last row without duplicate bands. The following application-specific checks remain **unverified**:

1. Open Google Sheets and Lark Sheets in Chrome. Scroll capture a range covering at least three viewports. Check that row numbers increase in order, with no duplicated bands. Repeat and press `Esc` halfway through; the partial image should open in the editor.
2. Open a long PDF in a desktop reader, then an Excel workbook. Repeat the scroll test. Try Manual when the reader or sheet does not respond to automatic input.
3. Check area/window capture, capture delay, crop auto-scroll near the editor viewport edge, PNG save/copy, and MP4 Start/Stop/Cancel on the target PC. Stop should open the video preview; Save As should appear only after pressing Save MP4. Try Copy Clip then paste in LINE PC, and drag from the grip icon if the client does not accept pasted files.

Automatic scrolling cannot be guaranteed for every app. SnapCraft stops after unchanged frames rather than saving a repeated viewport. If a join cannot be verified, it switches to Manual. Capturing protected or hardware-accelerated windows may be blocked by Windows or the app itself.

See [0.1.20 release notes](docs/release-0.1.20.md). Run `node tests/layer-order.cjs` for pixel, history, ownership and responsive-toolbar checks.

Version 0.1.19 was updated on 2026-10-06. About identifies jairlinethai, the update date and a short list of changes. Setup offers checked launch, Desktop shortcut and Windows startup options on new installations. Updates preserve existing settings and startup preference, ask the user to exit the running application, and reject downgrades. New installations use Ctrl+PrtSc for area capture; saved bindings remain unchanged. Windows startup uses --tray, with the startup toggle available in the tray menu. See [release notes](docs/release-0.1.19.md) for verification and remaining limitations.

`node tests/editor-project.cjs` exercises exact image pixels, vertical/horizontal composition, editable round-trip, owner movement/resize/crop/deletion, undo/redo, invalid-project preservation, imports and responsive layout. `SnapCraft.Tests.exe --projects` checks the real Windows editor, additional tabs, source independence, embedded-project loading, locked-output preservation and safe close. Generated fixtures are used, not real documents. Hardware-dependent live capture is unchanged and requires the existing pilot tests.

- Scroll footer detection is re-evaluated across joins rather than permanently accepting a zero-height first result. Up to 160 look-behind rows per strip retain the original pixels needed to trim an initially changing or hidden footer once it becomes recognizable. A stationary bottom band is excluded at both match endpoints when computing displacement. Generated tests cover temporal footer changes, variable row heights, thin separators and no-footer sheets, comparing exact output body pixels. These reproduce possible causes, not a verified live-Lark root cause.
- `node tests/editor-view-tail.cjs` checks native backing/export invariance, view-only history/dirty state, four-direction pointer pixels, legacy silhouette, crop-edge dragging, body move/resize/edit, interruption cleanup and compact desktop/narrow layouts. Native tests also check GPU coordinate mapping at negative monitor origins and source-size ratios; physical mixed-DPI multi-monitor verification remains required.

- `node tests/annotation-effects.cjs` checks rendered 5px defaults, shadows on every annotation, outline pixels and color independence, single-interaction history, bubble wrapping/move/resize/edit/cancel, palette routing, crop/export and blur protection. Test images are generated locally. Rebuild used icons without changing extension assets with `node tools/build-assets.cjs --windows-only --icons-only`.

- New checks: `node tests/stroke-numbering.cjs`, `node tests/video-preview.cjs` (requires FFmpeg), native `--video-preview --recording-preview` for actual local media, close/cancel/clipboard lifetime, and recording-stop handoff. Default native tests cover MP4 atomic save and pinned retention. Test-generated media is used; no real chats or document data are packaged.

- `powershell -NoProfile -File tests/installer-completion.ps1` exercises the actual installer success branch without changing the machine. `node tests/team-readiness.cjs` checks compact launcher bounds, truthful activity, dialog layout messages, and editor kept-state/copy/export semantics. Native `--editor --launcher --exit-editors --assets` checks close confirmation, canceled PNG save, tab cleanup, new captures arriving during close, launcher restoration, and canceling application exit. The default suite checks locked-output preservation and PNG save retry. Clean-PC installation and multi-device recording still require pilot testing.

- Scroll footer detection recognizes sparsely changing, broad gray 1-2px separators supported by stationary rows below. Lark's canvas colors can bleed through these rules even when the scrollbar does not move; treating the first changed rule as the start of content left the scrollbar repeated at each join. Regression tests compare exact body pixels, one frozen header, and the final footer. `--lark-chrome <before.png> <after.png>` replays the scrollbar pixels from the supplied October screenshots over a generated body; private cell data is not stored or distributed. This is not a live Lark end-to-end test.

- Light scroll footers no longer require a dark background. A stationary partial-width scrollbar edge is checked against the measured body displacement, then its flat padding is retained with the footer once at the end. This prevents light scrollbar/status bands from being inserted at each join. Native regression tests compare exact content pixels for white/light footers and a table with no footer. Live Lark validation is still required on the target PC.

- Editor gestures end and release pointer capture before Escape, Undo/Redo, Delete, Clear, or tool changes. Crop auto-scroll also stops when its gesture ends.
- Line, arrow, pen, and highlighter resizing uses diagonal projection to prevent near-horizontal/vertical strokes from jumping in size. Other shape scaling is unchanged.
- Crop rounds and clamps both endpoints before deriving dimensions, preventing transparent edge pixels after fractional or repeated crops. Annotations retain their original image coordinates and crop history remains undoable.
- `node tests/editor-edge-cases.cjs` verifies 31 editor regression cases, including interrupted mouse gestures, axis-aligned/reversed strokes, repeated crop history, exported edge pixels, and long-image crop auto-scroll. Requires Node.js and Playwright; set `PLAYWRIGHT_PATH` for its module location if needed. Evidence is saved in `dist/editor-edge-cases`.

- Single-click the notification-area icon to reopen the launcher. Reopening the EXE/desktop/taskbar shortcut restores the same instance, including after Close-to-tray or Minimize. Windows Forms' built-in single-instance application model handles IPC and foreground activation. Activation does not interrupt a capture or video finalization.
- Unchanged UI assets are not rewritten on startup; old capture cleanup and CPU-recorder discovery run after the launcher loads. Editor tabs reuse the launcher's WebView2 environment on the same UI apartment. Cold startup still depends on the installed WebView2 runtime and disk performance.
- Desktop/Start-menu shortcuts use a versioned blue ICO file and setup notifies the Windows shell to refresh icons without deleting the user's icon cache.
- `SnapCraft.Tests.exe --launcher --single-instance` checks native single-click tray activation, close-to-tray, minimize restoration, and repeated real EXE launches returning focus to the original process. Local warm measurements were about 20 ms for the tray and 0.37-0.87 seconds for EXE relaunch; cold WebView2 readiness varied from 1.4-2.8 seconds. These are local measurements, not guarantees for other PCs.

Activation follows the [Windows Forms single-instance application model](https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualbasic.applicationservices.windowsformsapplicationbase.startupnextinstance?view=windowsdesktop-8.0) with a foreground-permission handoff to the existing process using [AllowSetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-allowsetforegroundwindow). UI browser reuse follows Microsoft's [WebView2 performance guidance](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/performance). Installer refresh uses [SHChangeNotify](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotify).

Local visible-window measurements were approximately 0.1-0.2 seconds for capture/PNG encoding, excluding user selection, configured delay, and editor startup. Timings on other PCs vary.
- `--provided-sheet <png>` checks framing of supplied screenshots without saving or packaging the private input. Both supplied Lark examples were recognized with their original widths retained. This is a framing regression test, not a live Lark account test.

- Stroke width, color, and opacity update on every slider/input event. Each slider interaction creates one undo entry.
